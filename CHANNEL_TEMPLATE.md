# Добавление и сопровождение каналов

Актуально на **9 октября 2026**. Документ описывает всю цепочку: источник потока → Cloudflare Workers → мини-апп (этот репозиторий) → сайт [russian-tv.com](https://russian-tv.com) (репозиторий `russian-tv-site`).

---

## 1. Как всё устроено

```
Источник HLS (smotrim.ru, cinerama.uz, thestream.cyou, fs.uplink.kz …)
        │  плейлист (.m3u8)                        сегменты (.ts) идут напрямую
        ▼                                          от источника к зрителю
Cloudflare Workers (аккаунт dyaltd)  ─────────────────────────────────────▶ браузер / Telegram
  • russia-worker  (= https://stream.russian-tv.com, основной)
  • birch-creek
  • oak-valley
        ▲
        └── /stream?channel=<id>   ← сайт (русский и английский) и мини-апп
```

- Воркеры работают в режиме **«только плейлисты»** (CORS-only): они переписывают плейлист (абсолютные ссылки на сегменты, ссылки на вложенные плейлисты через `/playlist?url=`), а видеосегменты браузер берёт у источника напрямую. Проксировать сами сегменты нельзя (правила Cloudflare), маршрут `/proxy` намеренно возвращает 410.
- Сайт и мини-апп вызывают воркеры по очереди (порядок в `proxy.json` сайта и в массиве `PROXIES` мини-аппа) и при ошибке переключаются на следующий.
- **Идентификатор канала** (`id`) — один и тот же во всех слоях: ключ в воркере, `id` в мини-аппе, `CH_ID` на странице сайта.

## 2. Чеклист добавления канала

1. **Найти источник** и проверить его (см. раздел 3).
2. **Воркеры** — добавить канал во все три воркера (раздел 4) и в копию `russia-worker.js` этого репозитория.
3. **Мини-апп** — добавить объект в нужную группу `CHANNEL_GROUPS` в `index.html` (раздел 5).
4. **Сайт** — добавить страницы RU и EN, строки в боковые списки, главные страницы, страницы категорий и `sitemap.xml` (см. README репозитория `russian-tv-site`).
5. **Проверить** на живом сайте и в мини-аппе: запуск, звук, качество (если уровней несколько), смена канала.

## 3. Источники потоков

Подходит источник, который удовлетворяет всем условиям:

- **https** (на https-странице браузер блокирует `http://`-сегменты);
- плейлист и сегменты открываются из браузера с **CORS** (`Access-Control-Allow-Origin`);
- сегменты скачиваются быстрее, чем длятся (замер: время загрузки сегмента / его длительность, нужно заметно меньше 1);
- поток живой (в плейлисте меняется `EXT-X-MEDIA-SEQUENCE`) и **картинка движется** (были источники-«заставки»: плеер играл, кадр не менялся — такой канал, например «Патриот» на `smotrim.ru/hls2/static/`, удалён).

Типы записей в воркере (`russia-worker.js`):

| Где | Для чего | Пример |
|---|---|---|
| `STREAMS` | источник — готовый плейлист (одиночный или мастер с несколькими уровнями) | `ntv: "https://streaming.thestream.cyou/live/213.m3u8"` |
| `SYNTH_MASTERS` | воркер **собирает мастер-плейлист** из набора `playlist_N.m3u8` smotrim.ru, чтобы у канала появился выбор качества | `rossiya1: { dir: "hls2/russia_hd", ladder: [[1,486],[2,837],[3,2501],[4,4062],[6,6990]] }` (номер плейлиста, битрейт в кбит/с) |
| `CINERAMA_PATH` | каналы `cinerama.uz`: путь к плейлисту, воркер сам выбирает зеркало `stream1/3/8` | `kinohit: "1055/tracks-v1a1/mono.m3u8"` |
| `STITCHED_MASTERS` | зарезервировано (сейчас пусто) | — |

Порядок обработки в `/stream`: `SYNTH_MASTERS` → `CINERAMA_PATH` → `STITCHED_MASTERS` → `STREAMS`.

Практические правила:
- Если у источника есть **мастер-плейлист** с несколькими уровнями, указывайте именно его: на сайте и в мини-аппе тогда автоматически появится выбор качества. Закреплять один уровень (`…_2k_v5.m3u8`) не нужно.
- У `thestream.cyou` мастер — это `…/live/<id>.m3u8` (уровни 240p/360p/576p); варианты `1k/2k/3k` — отдельные уровни (1k — самый высокий).
- У `smotrim.ru` лесенка `hls2/<канал>/playlist_N.m3u8` (N = 1…6, пропуски возможны), прямой мастер `playlist.m3u8` требует подпись и возвращает 403.
- Каналы с `cinerama.uz` отдают один уровень; зеркала — независимые копии потока (разная нумерация сегментов), поэтому воркер не должен «прыгать» между ними (см. раздел 4).

## 4. Воркеры

### Маршруты

| Маршрут | Назначение |
|---|---|
| `GET /stream?channel=<id>` | плейлист канала (мастер или медиа-плейлист) |
| `GET /stream-q?channel=<id>&q=<кбит/с>` | то же, но мастер урезан до одного уровня, ближайшего к `q` (нужен iPhone/iPad с нативным HLS — hls.js там недоступен) |
| `GET /playlist?url=<источник>` | вложенные плейлисты, на которые ссылается переписанный мастер |
| `GET /version` | версия и число каналов |
| `GET /proxy` | отключён (410) |

### Поведение для `cinerama.uz`

- пропускает зеркало, если оно перенаправляет на `/blocked/`;
- проверяет сегмент запросом `Range: bytes=0-0` (предпоследний сегмент плейлиста); если сегмент недоступен — пробует следующее зеркало, а если не подошло ни одно — отдаёт первый рабочий плейлист;
- плейлист считается «протухшим», если последний сегмент старше **120 секунд** (`STALE_THRESHOLD_MS`); из «протухших» берётся самый свежий (не старше 5 минут).

### Деплой

- Основной код воркеров лежит **в Cloudflare** (Workers & Pages → воркер → Edit code, либо API `PUT /workers/scripts/<имя>/content`). Репозиторный файл `russia-worker.js` — **копия** для истории и ревью; после каждой правки воркера её нужно синхронизировать вручную.
- У `birch-creek` и `oak-valley` линия кода другая (v82.33.x, с комментариями и без проверки «протухшего» плейлиста); одни и те же записи каналов надо вносить во все три воркера. Откат — Versions в Cloudflare.
- ⚠ Скрипт `deploy-russia-worker.command` публикует файл `~/russia-tv-hub/russia-worker.js`. Запускайте его только если этот файл совпадает с боевым кодом, иначе можно откатить воркер на старую версию.
- Строка `VERSION` в воркерах сейчас не поднимается при мелких правках (`/version` показывает 82.35.0).

Проверка после правки:

```bash
curl -s "https://stream.russian-tv.com/stream?channel=<id>" | head -20      # плейлист отдаётся
curl -s "https://stream.russian-tv.com/stream-q?channel=<id>&q=800" | head   # один уровень
```

## 4a. Выбор качества

- **Сайт:** файл `assets/quality.js` (кнопка «⚙ Качество: …» в панели плеера). Если у потока больше одного уровня, кнопка появляется сама; режим «Авто» — адаптивный (hls.js стартует с низкого уровня и растёт).
- **iPhone/iPad (нативный HLS):** уровни читаются из мастер-плейлиста, а фиксированный уровень включается через `/stream-q`.
- **Мини-апп:** функции `initQuality(hls)` (hls.js) и `initQualityNative(streamUrl)` (iOS), кнопка `#quality-btn` в панели `.controls`. В мини-аппе включён `capLevelToPlayerSize`: в режиме «Авто» уровень не выше размера плеера.
- Выбор хранится в `localStorage` (`rtv_quality`: `auto`, высота `720` или битрейт `b2500`).

## 5. Мини-апп: запись канала

Каналы заданы в `index.html` массивом групп `CHANNEL_GROUPS` (одна группа = одна тема в хабе):

```js
const SITE = 'https://russian-tv.com';
const CHANNEL_GROUPS = [
  { label: '📡 Новости и общие', channels: [
    { id:'rossiya1', name:'Россия 1', desc:'Главный федеральный канал', icon:'Р1',
      color:'#D52B1E', iconBg:'#1a0808',
      logo: SITE+'/assets/logos/rossiya1.svg',      // необязательно
      slug: 'rossiya-1-live',                       // необязательно: кнопка «Смотреть на сайте»
      stream: PROXY+'/stream?channel=rossiya1' },
    …
  ]},
  …
];
```

- `PROXY` — текущий воркер из массива `PROXIES` (порядок: `birch-creek`, `stream.russian-tv.com`, `oak-valley`); переключается при ошибках.
- Без `slug` кнопка «Смотреть на сайте» не показывается (так сделано для каналов, которых нет на сайте: Россия-К, Москва 24 в мини-аппе).
- Группы сейчас: Новости и общие · Развлечения · Кино · Детские · Музыка · Хобби и стиль · Спорт.
- Карточки в хабе создаёт `buildHub()`, по клику вызывается `openChannel(ch)` — регистрировать ничего больше не нужно.

### Какой канал к какой теме

Критерий — содержание канала, а не источник. Примеры, где ошибались: «Рыжий» — детский, «Бобер» — «Хобби и стиль», «Честный детектив» — кино, «Соловьёв Live» — новости. На сайте темы совпадают с мини-аппом (на сайте «Хобби и стиль» называется «Хобби»).

## 6. Кнопки плеера мини-аппа

Все кнопки находятся в `.controls` внутри `.overlay`. Overlay автоскрывается через 4 секунды в режиме fullscreen, тап по видео показывает его снова.

| Кнопка | ID | Когда видна | Поведение |
|---|---|---|---|
| 🔄 Переподключиться | `#reload-btn` | только при ошибке | сбрасывает паузу, вызывает `init()` |
| 🔊 Включить звук | `#unmute-btn` | после старта потока (не в аудио-режиме) | переключает `video.muted`, при unmute отключает `audio-bg` |
| 🎧 Только звук | `#mode-btn` | всегда | скрывает видео, оставляет звук |
| 🔳 Полный экран | `#fullscreen-btn` | всегда | разная логика для iOS и Android (раздел 7) |
| 🎥 PiP | `#pip-btn` | только на ПК | `requestPictureInPicture` |
| ⚙ Качество | `#quality-btn` | если у канала больше одного уровня | меню «Авто» + уровни (раздел 4a) |

Тексты берутся из объекта `T[lang]`. Для новых строк добавляйте ключ во все языки (`ru, bg, en, de, fr, es, uk, tr`); подписи кнопки качества сейчас русские/английские.

## 7. Fullscreen

### Android

```
container.requestFullscreen()
  → успех: нативный fullscreen, шапка Telegram исчезает
  → ошибка: fallback на CSS-класс .css-fs (position:fixed, inset:0, z-index:9999)
```

`video` должен быть **вне** `.overlay` (прямой потомок `#video-container`), иначе при автоскрытии интерфейса видео гаснет.

### iOS (Telegram WebView)

```
video.webkitEnterFullscreen()   // нативный iOS плеер
```

- `isIOS()` проверяет `userAgent`, `navigator.platform` + `maxTouchPoints` **и** `window.Telegram?.WebApp?.platform === "ios"` (последнее критично: WebView отдаёт нестандартный UA);
- выход ловится событием `webkitendfullscreen`, затем поток перезапускается (`stopStream()` + `init()`, задержка 300 мс), иначе iOS зависает.

## 8. Аудио-сессия (фон)

- **Android:** элемент `<audio id="audio-bg" muted>` с отдельным `hlsAudio`; когда вкладка уходит в фон, звук переходит на него, при возврате обратно на `video`.
- **iOS:** Media Session API (`setupMediaSession()`), управление с экрана блокировки.
